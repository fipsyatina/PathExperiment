# PathExperiment

![Покроковий пошук маршруту](docs/media/search.gif)

![Порівняння Dijkstra та A*](docs/media/comparison.png)

PathExperiment — настільний C++20 застосунок для створення карт, покрокового спостереження за пошуком маршруту та порівняння Dijkstra й A*. Він також слугує окремим стендом для майбутньої навігації юнітів у Ribterra.

[Завантажити готову Windows x64 версію](https://github.com/fipsyatina/PathExperiment/releases/latest). Розпакуйте ZIP та запустіть `PathExperiment.exe`, залишивши `assets/` і `maps/` поруч. Мова інтерфейсу першої версії — англійська.

## Керування

Ліва кнопка миші застосовує вибраний інструмент. Права повертає клітинку до звичайної місцевості.

| Клавіша | Дія |
| --- | --- |
| `1` | Дорога |
| `2` | Звичайна місцевість |
| `3` | Болото |
| `4` | Стіна |
| `5` | Старт |
| `6` | Ціль |
| `Space` | Запустити або призупинити пошук |
| `N` | Виконати один крок |
| `R` | Скинути візуалізацію пошуку |
| `C` | Очистити карту |
| `Tab` | Перемкнути алгоритм |
| `B` | Порівняти Dijkstra та A* |
| `Ctrl+S` | Зберегти карту у файл з унікальною часовою позначкою |
| `Ctrl+O` | Відкрити `.pemap` через системний вибір файлу на Windows; на інших системах завантажити останнє збереження |

Кнопки інтерфейсу дублюють ці дії. Кнопки `<`, `>` і `Load example` дозволяють вибрати та відкрити готовий приклад. Підказка для клітинки показує координати, вартість входу та доступні `g`, `h`, `f` і попередню клітинку.

Помаранчева лінія — поточний кандидат шляху, зелена — фінальний оптимальний маршрут. Сині клітинки показують опрацьовані гілки, зокрема тупикові; червоні позначки — відхилені переходи до сусідів. Пауза та `N` дозволяють роздивитися кожну перевірку. Відхилення переходу через стіну, вже опрацьовану клітинку або відсутність покращення вартості не означає помилку алгоритму.

Швидкість анімації — 1–60 клітинок на секунду. Кожне розгортання отримує окремий кадр; якщо відображення сповільниться, анімація теж сповільниться, щоб зберегти всі кроки.

Нові карти зберігаються з унікальною часовою позначкою. На Windows каталог збережень — `%LOCALAPPDATA%\PathExperiment\maps`. На Linux застосунок використовує `$XDG_DATA_HOME/PathExperiment/maps`, а якщо `XDG_DATA_HOME` не задано — `~/.local/share/PathExperiment/maps`.

## Збирання

Потрібні CMake 3.28 або новіший, компілятор із підтримкою C++20 та доступ до мережі під час першої конфігурації. CMake автоматично завантажує SFML 3.1.0.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Графічний застосунок і копії потрібних ресурсів будуть у `build/bin/`. Запускайте `build/bin/PathExperiment.exe` на Windows або `build/bin/PathExperiment` на Linux.

На Windows установіть компонент Visual Studio «Desktop development with C++». На Ubuntu для графічної збірки потрібні `libxrandr-dev libxcursor-dev libxi-dev libudev-dev libgl1-mesa-dev libegl1-mesa-dev`. Ядро та його тести не потребують цих графічних залежностей.

Для збирання та тестування лише алгоритмів без SFML:

```sh
cmake -S . -B build -DPATHEXPERIMENT_BUILD_APP=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Цей варіант створює бібліотеку `pathx_core` і виконуваний файл тестів `pathx_tests`.

## Правила руху

Рух можливий угору, униз, ліворуч і праворуч. Вартість маршруту — сума вартостей клітинок, у які входить маршрут; стартова клітинка не враховується.

| Місцевість | Вартість входу |
| --- | ---: |
| Дорога | 1 |
| Звичайна | 2 |
| Болото | 5 |
| Стіна | непрохідна |

Dijkstra обирає клітинку за вже накопиченою вартістю. A* додає мангеттенську оцінку відстані до цілі: `f = g + h`. За цих правил обидва алгоритми знаходять мінімальну вартість, хоча за наявності рівноцінних варіантів їхні маршрути можуть відрізнятися.

## Результати й вимірювання

- **Steps** — кількість переходів у знайденому маршруті.
- **Cost** — сумарна вартість входу в клітинки маршруту.
- **Expanded** — кількість клітинок, розгорнутих алгоритмом, включно з ціллю.
- **Median** — медіана часу обчислення в мікросекундах.

Порівняння виконує один прогрів і 31 незалежний вимірюваний запуск кожного алгоритму. Ініціалізація пошуку та відновлення маршруту входять у вимірювання; відображення й штучні затримки не входять. Для порівняння продуктивності використовуйте Release-збірку.

## Відтворення демонстрації

`PathExperiment --record-demo captures` зберігає кадри реального SFML-вікна. `python tools/make_demo.py captures docs/media/search.gif` створює GIF із цих кадрів; для скрипту потрібен Pillow. Використовуйте нові шляхи, щоб зберегти попередні результати. `--smoke-test captures` перевіряє введення, стан пошуку, збереження та приклади й робить нативні знімки.

Для включення нативної перевірки до CTest задайте `-DPATHEXPERIMENT_ENABLE_GUI_TESTS=ON` під час конфігурації; потрібен доступ до графічного дисплея. Повторний запуск перевірки створює новий каталог знімків і зберігає попередні результати.
